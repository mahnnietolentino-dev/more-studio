# MoRe Studio v0.1 — Packaging Specification (.more)

## 1. Overview

The `.more` file is a packaged learning unit generated by MoRe Studio.

It is a structured container that includes:

* Chapters (HTML)
* Quizzes (JSON)
* Media assets (images)
* Metadata and manifest files

The `.more` format is designed to be:

* Portable
* Offline-capable
* Easy to parse
* Deterministic

---

## 2. File Format

`.more` is a ZIP-based container.

Example:

```
book.more = ZIP archive
```

---

## 3. Directory Structure

```
book.more
│
├── manifest.xml
├── metadata.xml
│
├── chapters/
│   ├── ch1.html
│   ├── ch2.html
│
├── quizzes/
│   ├── ch1.json
│   ├── ch2.json
│
├── assets/
│   ├── img1.jpg
│   ├── img2.png
│
└── index.html
```

---

## 4. Core Files

### 4.1 manifest.xml

Defines the structure and contents of the package.

**Purpose:**

* Lists all files
* Defines chapter order
* Links quizzes and assets

---

### Example

```
<manifest>
  <chapters>
    <chapter id="1" file="chapters/ch1.html" />
    <chapter id="2" file="chapters/ch2.html" />
  </chapters>

  <quizzes>
    <quiz chapter="1" file="quizzes/ch1.json" />
  </quizzes>

  <assets>
    <asset file="assets/img1.jpg" />
  </assets>
</manifest>
```

---

### 4.2 metadata.xml

Contains descriptive information about the book.

---

### Example

```
<metadata>
  <title>Sample Book</title>
  <author>Mahnnie Tolentino</author>
  <version>1.0</version>
  <created_at>2026-03-19</created_at>
</metadata>
```

---

## 5. Chapters

* Stored as HTML files
* Derived from DOCX content
* Split using Heading 1

---

### Naming Convention

```
ch1.html
ch2.html
...
```

---

## 6. Quizzes

Stored as JSON files per chapter.

---

### Example

```
[
  {
    "type": "MCQ",
    "question": "What is 2 + 2?",
    "choices": [
      {"text": "3", "correct": false},
      {"text": "4", "correct": true}
    ]
  }
]
```

---

## 7. Assets

* Images extracted from DOCX
* Optimized using ImageMagick
* Referenced inside HTML

---

## 8. index.html

Entry point for rendering the package.

**Responsibilities:**

* Load chapters
* Navigate content
* Interface with quizzes

---

## 9. Packaging Process

1. Generate all components:

   * Chapters
   * Quizzes
   * XML files
   * Assets

2. Organize into directory structure

3. Compress into ZIP

4. Rename `.zip` → `.more`

---

## 10. Design Principles

### 10.1 Portability

Packages must run without internet.

---

### 10.2 Determinism

Same input → identical output.

---

### 10.3 Simplicity

Structure must be easy to parse by any system.

---

### 10.4 Extensibility

Future features can be added without breaking existing packages.

---

## 11. Versioning

The `.more` format should support versioning via:

```
<version>1.0</version>
```

Future changes must remain backward-compatible.

---

## 12. Validation Rules

A valid `.more` package must include:

* manifest.xml
* metadata.xml
* At least one chapter
* Proper file references

---

## 13. Future Enhancements

* Embedded analytics
* Interactive components
* Video/audio support
* Localization support
* Encryption (optional)

---

## 14. Summary

The `.more` format is the core delivery unit of the MoRe ecosystem.

It enables:

* Structured learning
* Offline accessibility
* Scalable distribution

It is the bridge between **content creation (MoRe Studio)** and **content consumption (MoRe container app and compatible systems)**.
