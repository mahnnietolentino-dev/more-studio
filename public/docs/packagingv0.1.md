# MoRe Studio v0.1 — Packaging Specification (.more)

## 1. Overview

The `.more` file is a packaged learning unit generated by MoRe Studio.

It is a structured container that includes:

* Chapters (HTML)
* Quizzes (JSON)
* Media assets (images)
* Metadata and manifest files

The `.more` format is designed to be:

* Portable
* Offline-capable
* Easy to parse
* Deterministic

---

## 2. File Format

`.more` is a ZIP-based container.

Example:

```
book.more = ZIP archive
```

---

## 3. Directory Structure

```
book.more
│
├── manifest.xml
│
├── chapters/
│   ├── ch1.html
│   ├── ch2.html
│
├── quizzes/
│   ├── ch1.json
│   ├── ch2.json
│
├── assets/
│   ├── img1.jpg
│   ├── img2.png
```

---

## 4. Core Files

Defines the structure and contents of the package.

**Purpose:**

* Lists all files
* Defines chapter order
* Links quizzes and assets

---

### Example

```
<manifest>
  <chapters>
    <chapter id="1" file="chapters/ch1.html" />
    <chapter id="2" file="chapters/ch2.html" />
  </chapters>

  <quizzes>
    <quiz chapter="1" file="quizzes/ch1.json" />
  </quizzes>

  <!--Future implementation
  <assets>/(optional)
    <asset file="assets/img1.jpg" />
  </assets>
  -->
</manifest>
```

---

### Example

```
<metadata>
  <title>Sample Book</title>
  <format>MoRe</format>
  <formatVersion>1.0</formatVersion>
  <formatCreator>Mahnnie Tolentino</formatCreator>
  <generator>MoRe Studio</generator>
  <author>Mahnnie Tolentino</author>
  <version>1.0</version>
  <created>2026-03-20</created>
</metadata>
```

---

## 5. Chapters

* Stored as HTML files
* Derived from DOCX content
* Split using Heading 1

---

### Naming Convention

```
ch1.html
ch2.html
...
```

---

## 6. Quizzes

Stored as JSON files per chapter.

---

### Example

```
[
  {
    "type": "MCQ",
    "question": "What is 2 + 2?",
    "choices": [
      {"text": "3", "correct": false},
      {"text": "4", "correct": true}
    ]
  }
]
```

---

## 7. Assets

* Images extracted from DOCX
* Optimized using ImageMagick
* Referenced inside HTML

---

## 8. index.html

Entry point for rendering the package.

**Responsibilities:**

* Load chapters
* Navigate content
* Interface with quizzes

---

## 9. Packaging Process

1. Generate all components:

   * Chapters
   * Quizzes
   * XML files
   * Assets

2. Organize into directory structure

3. Compress into ZIP

4. Rename `.zip` → `.more`

---

## 10. Design Principles

### 10.1 Portability

Packages must run without internet.

---

### 10.2 Determinism

Same input → identical output.

---

### 10.3 Simplicity

Structure must be easy to parse by any system.

---

### 10.4 Extensibility

Future features can be added without breaking existing packages.

---

## 11. Versioning

The `.more` format should support versioning via:

```
<version>1.0</version>
```

Future changes must remain backward-compatible.

---

## 12. Validation Rules

A valid .more package MUST:

* Contain manifest.xml at the root
* Contain at least one chapter file
* Ensure all referenced files exist
* Use relative paths inside the archive

## 12.1 Root Structure Rule

All files and directories MUST exist at the root of the .more archive.

The archive MUST NOT contain nested parent directories such as:

/storage/
/processing/
/build_1/

Example of INVALID structure:

book.more
└── storage/
    └── processing/
        └── build_1/
            └── manifest.xml

The `.more` format is the core delivery unit of the MoRe ecosystem.

It enables:

* Structured learning
* Offline accessibility
* Scalable distribution
